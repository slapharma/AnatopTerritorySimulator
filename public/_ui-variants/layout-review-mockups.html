Layout review — mockups

Two verified HIGH findings from a live check against /interfaces:better-layout. Each frame below is the real chrome and real CSS — only the one rule named under "After" changed.

HIGHWar Room tabs: 2 of 5 hidden with no scroll cue

public/styles.css:228 — .tabs { overflow-x: auto }

Before

Minutes and Intelligence are entirely off-screen at the panel's default 340px width. No fade, arrow, or partial-tab peek hints they exist — a viewer has to know to scroll a tab strip sideways to find them.

After — .tabs { flex-wrap: wrap }, drop overflow-x

All 5 tabs visible at once, wrapped to a second row. No hidden content, no scrolling, same panel width.

HIGHAdmin table: row actions clipped off-screen on mobile

public/admin.html:17 — .row-actions { display: flex; gap: 8px } (no wrap, no scroll container)

Before, 375px viewport

Three unwrapped buttons force the table wider than the viewport. The whole page scrolls horizontally to reach "Remove" — verified: last button's right edge lands past the visible viewport, page requires a horizontal scroll the layout gives no visual hint exists.

After — .row-actions { flex-wrap: wrap }

Buttons wrap onto a second line inside their own cell. Table stays within the viewport, page doesn't scroll, every action reachable without hunting.
